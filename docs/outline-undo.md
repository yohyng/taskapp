# 受信した変更を残すUndo（v1.15.27）

以前のUndoは履歴にある文書全体を戻していた。その後に受信した別端末の本文・追加・削除まで
過去の状態へ戻し、通常の編集としてサーバーへ送ってしまう。

## 取り消す範囲

- 履歴には自分の操作の前後を記録する。受信した変更は積まない。
- Undoは操作後と操作前の差だけを、現在の文書へ重ねる。Redoも実際に戻した差だけを使う。
- 文字・色・日付・完了・見出し・画像幅などは、変更した属性だけを戻す。
  同じ行に届いた別の属性や子、別の行の本文・追加・削除は残す。
- 配置は親と兄弟の相対関係で確認する。挿入・削除による番号のずれを全行の移動とは扱わない。
  受信した行を残したうえで、自分が移動した行や削除した枝を配置し直す。
- 対象の本文・配置が別端末で変更済み、削除対象に新しい子がある、戻し先の親が消えた、
  親子が循環する場合は操作全体を保留する。途中まで変更して残りだけ失敗させない。

保留時は現在の文書・操作履歴・未送信キューを変更せず、理由を小さく表示する。
同期全体を止めたり「確認が必要」へ切り替えたりはしない。
履歴は従来と同じく、開いている間の最大100手をメモリー内に保持し、再起動後の復元対象にはしていない。
保留した操作の比較・強制適用・スキップ画面は今回追加していない。

## 入力と明示的な置き換え

同じ行で900ms以内に続けた入力は一手にまとめる。ただし受信が間へ入ったときは履歴を分け、
受信内容を自分の編集へ混ぜない。自分が送った内容と同じ通知は既存の処理で受信対象から除く。

「向こうに合わせる」は未送信を捨てて最新へ明示的に置き換える操作なので、Undo/Redo履歴も消す。
破棄した編集や受信内容を、Undoから再送できる状態にはしない。

## 検証

- 修正前のブラウザーで、別の行を受信したあとUndoすると、その受信が古い本文へ戻ることを再現。
- 純粋関数の21ケースで、属性・追加・削除・並べ替え・字下げ・親消失・循環・競合の保留と
  11,000行の並べ替えを確認。
- Chromium/WebKitで本文・色・子行の保持、受信を挟む入力、Undo/Redo、送信中の削除取り消し、
  明示的な取り込み後の履歴破棄を確認する。
- ローカルで単体371件と本番ビルドが成功。差分に新しいESLintエラーなし。
