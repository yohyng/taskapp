## いまの持ち物（前提）

React 19 + Vite 8 + Tailwind v4。部品のライブラリは入れていない。
入っているのは dnd-kit / framer-motion / lucide-react / supabase-js / perfect-freehand だけ。
`AGENTS.md` の約束どおり、**依存は勝手に増やさない**。ここの道具を入れるときは相談してから。

## 土台（部品の作りそのもの）

| | 何者か | この app との相性 |
|---|---|---|
| [shadcn/ui](https://ui.shadcn.com) | 部品の**コードを自分のリポジトリへ写して使う**方式（依存にしない）。Radix + Tailwind が土台。CLI で追加 | Tailwind v4 なので土台は合う。依存が増えないのが利点。ただし今の手作りの見た目と二重になりやすい |
| [Base UI](https://base-ui.com) | 見た目を持たない部品（ヘッドレス）。Radix・MUI・Floating UI の作者たちが合流して作っている後継 | Radix の置き換え候補。新しいぶん、枯れ具合は要確認 |
| [Radix](https://www.radix-ui.com) | 見た目を持たない部品の定番。ダイアログ・ポップオーバー・メニューなどの「操作と支援技術まわり」を引き受ける | いまは自前（枠・メニュー・設定シート）。作り直すなら土台として堅い |

## 選び方のスキル

[pick-ui-library スキル](https://github.com/emilkowalski/skills) … Emil Kowalski が公開している
「どの UI ライブラリを選ぶか」を助けるスキル集。Claude Code のスキルとして入れられる。

## この app に入れるとしたら（私見）

1. **Sonner / Vaul / cmdk** … 単機能で、入れても世界観が壊れない。効き目もはっきりしている
2. **Base UI か Radix** … ダイアログやメニューを作り直すときの土台として。入れるなら一気にではなく一か所から
3. **shadcn/ui** … 使うとしても「写して自分のものにする」方式。全面的に乗り換える話ではない
4. **見本集（Magic UI ほか）** … 必要なときに一部を写す。依存にはしない

どれも、いまの手作りの部品が困っていないうちは急がない。
困っているのは手書きの書き味と同期で、そこは部品の問題ではない。
