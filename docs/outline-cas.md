# アウトラインの古い端末保護（v1.15.13、サーバー境界）

個人が複数端末を行き来する使い方では、同時共同編集よりも、久しぶりに開いた端末が
新しい本文を押しのけないことを優先する。`docs/sql/outline-cas-v1.sql` はそのための
条件付き保存（CAS）と操作IDによる再送の重複排除を用意する。

クライアントは本文と `taskspace_outline_heads()` の世代を読み、変更ごとに読んだ世代を
`expected_revision` として送る。現在の世代と一致しない変更が1件でもあれば、同じ操作の
本文は一切変更せず `conflicts` を返す。端末時計の新旧では判定しない。

同じ `operation_id` と同じ内容を再送した場合は最初の結果を返す。通信が切れて返事だけを
失っても、同じ変更を二重に適用しない。別内容で同じIDを使った場合は拒否する。

v1.15.14ではクライアントの永続キューへ世代と操作IDを接続する。入力は従来どおり先に
画面と端末へ反映し、送信時だけCAS RPCを使う。RPC未導入なら従来保存へ戻るが、導入済みの
通信失敗では直接保存へ抜けない。返事を失った再送では保存済みの操作IDを使う。

既存クライアントを壊さないため、`outline_nodes` への従来の直接保存はまだ止めない。
本番へは履歴SQL、CAS SQL、対応クライアント、直接保存の停止の順で移行する。CASに対応して
いない古いPWAが残る間は、サーバー境界の保護が完成した扱いにしない。

競合時はクライアントの未送信記録を消さず、設定内からJSONへ書き出せる。ユーザーが控えを
取ったあと「向こうに合わせる」を選ぶと、本文とサーバー世代を一緒に読み直す。通常の編集は
これまでどおり手元へ即時反映し、競合がない送信の体感は変えない。
