# 画像の貼り付けとサイズ変更（v1.15.28、未配信）

## 修正した動作

アップロード完了時は、開始時の画面の写しではなく現在の文書へURLを置く。
元の行がまだ空ならその行へ置き、待っている間に本文を書いた場合は本文を残して画像行を後ろへ追加する。
行が移動していても現在の場所へ付ける。行が消えた場合は元の親の末尾へ、親も消えていれば
ホームの末尾へ置く。削除した行や親を復活させてまで置かない。

編集欄への画像ドロップが親の一覧にも伝わり、同じ画像を2回アップロードする経路を止めた。
ドラッグ中はブラウザーがファイル本体を隠す場合があるので、受け入れ判定はファイルの種類で行う。
本文の貼り付けは従来の処理へ渡す。

画像のつまみは常時見える24pxの領域にし、スクロールとの取り合いを避ける。
操作を始めた指のIDだけで幅を変更し、指を離したときだけ保存する。pointercancel・捕捉解除・
ウィンドウのフォーカス喪失・ペイン終了では保存せず、最新の保存幅へ表示を戻す。
操作中に同じ行が別の画像へ切り替わった場合も、古い画像の幅を送らない。

URLと幅の送信には従来の行単位キュー・世代確認を使う。GAS・SQL・保存形式は変更していない。

## 検証した範囲

- 修正前に二重送信、待機中の本文上書き、pointercancel後に表示幅だけが残る問題を再現した。
- 単体378件。画像用の7ケースでは空行・本文・移動・削除・親消失・複数の完了応答とドラッグの種類判定を確認した。
- Chromium/WebKitの新しい画像試験14ケースで、貼り付け・ドロップ・本文や削除の保護・中断・
  別の指による誤確定の防止・画像切り替え中の幅の保護を確認した。
- 幅390px・タッチ有効の別ブラウザー環境へ、サーバー役の写しを読み戻した。
  同じ画像URL・幅を表示し、開いただけでは書き戻さないことを確認した。
- 既存の画像・Drive・控え操作19件と本番ビルドが成功。差分に新しいESLintエラーなし。
  旧Drive試験の返事を現行のバックアップ照合へ合わせ、CIにもDrive操作を加えた。

画像ファイルとClipboardEvent・DragEvent・PointerEventは試験用に作り、GAS通信は代替応答で動かした。
実際のDriveへのアップロード、OSのクリップボード、iPad/Androidの実機操作を試験したものではない。
画像のオフライン送信待ち保存、写真形式の変換、一度に複数枚を取り込む処理は今回追加していない。

## 本番配信後の実機確認

PC・iPad・Androidでそれぞれ普段のコピー元から画像を1枚貼り、本文を壊さず表示されることを確認する。
アップロード待ちに文字を追記できること、指で幅を変えたあと別端末でも同じ幅を読み込むこと、
画面の切り替えでドラッグが中断されても見た目と保存値が食い違わないことを確認する。
実機でだけ起きる場合は、コピー元・画像形式・使った端末を記録して次の修正対象とする。
