# 同じ行への両立する変更を合わせる

v1.15.30。ひとりが端末を持ち替えて使うための同期を改善する。
文字単位の共同編集は行わず、編集前・手元・サーバーの三つを項目ごとに比較する。

## 自動で合わせる範囲

- 本文と折りたたみ、本文とお気に入り、色と画像幅など、違う項目への変更を両方残す。
- 同じ項目でも、双方が同じ値にした場合は競合にしない。
- サーバーに目的の状態が既にある場合は、更新時刻だけの追加保存をしない。
- 自分の編集をUndoで取り消した場合、残る目的がサーバーと同じなら未送信を解消する。
- 送信中に書き続けた編集は、受理された要求の本文を新しい比較基準にする。

本文・折りたたみ・完了・お気に入り・日付・見出し・文字色・背景色・画像幅と作成時刻を比較する。
更新時刻は本文の勝敗に使わない。比較用の時刻表記の正規化も、保存する時刻の表記へ持ち込まない。
画像URLの差し替えと元画像の幅変更は別々の項目でも重ねない。幅は画像そのものに結び付くため。

## 保存の条件と再送

サーバーのCAS条件は引き続き行の世代。項目比較を理由に、この条件を飛ばさない。
送信前から世代の相違を知っている場合は、先に比較する。
送信後に拒否された場合は、その要求全体が適用されなかったことを確認してから比較する。

比較前は世代一覧→本文→世代一覧を読み、二つの一覧が一致した場合だけ使う。
すでに知っている世代より古い読み出しも採用しない。確認中の追加入力や手動取り込みを
古い返事で消さず、現在の内容から比較し直す。

不適用が確定した要求は、元の操作IDへ別の内容を付けず、新しい要求へ移す。
返事を失っただけの要求は、元の本文・順序・世代・操作IDを保って確認する。
送る前の端末保存、サーバーでの世代確認、操作IDによる二重適用防止は維持する。

## 保留は該当箇所だけ

同じ本文を異なる値にした場合は、サーバーと端末の両方を保持する。
未送信記録の `blocked: true` がその行の送信を止め、他の本文や属性の編集は続ける。
再起動しても保留を忘れず、同じ拒否要求を繰り返し送信しない。

保留中の行のサーバー世代が変わったら自動で比較し直す。目的が満たされていれば保留を外す。
保留中の行を新たに編集した場合も、最新の意図を改めて比較できる。
通知を閉じたあとは、別の行を編集しただけでは大きな通知を再表示しない。
「確認が必要」の表示は残し、押すと詳細を開ける。通知を閉じてもデータや保留は消さない。
閉じたことは作業中だけ共有し、アプリを開き直した場合は未解消の保留を知らせる。

端末保存の形式名は `taskspace-outline/1` のまま。
省略可能な真偽値 `blocked`・`rebased` と、拒否済みのID `rejectedOperationId` を未送信記録へ追加する。
`rebased` の保存後は、通常の読み直しでサーバーの最新の位置も表示へ反映する。
SQL・GASの更新は不要。

## 今回自動化しない範囲

- 同じ本文の異なる編集は、文字単位に混ぜない。
- 比較基準の無い旧操作は、世代が一致しただけで新しい意味を推測しない。
- 古い基準からの移動・並べ替え・削除は、属性編集と同じ方法で統合しない。
- 比較した一団の構造に保留がある場合、その一団の構造はまとめて保留する。
  兄弟の番号変更や親子の削除の片方だけを適用して、別の操作に変えないため。
- 再送で親の無い行や輪を作らず、新しい子が残る親の削除も保留する。

競合内容を並べて選ぶ専用画面や、全体バックアップの復元画面は別の課題。
既存のJSON書き出し・手動取り込みは残すが、通常の持ち替えの手順にはしない。
実機3台でのv1.15.29の安定確認と、画像PR #23の本番統合はまだ別途残っている。

## 検証

修正前のブラウザーで「本文と折りたたみでも止まる」「一行の競合で別の行も止まる」を再現した。
純粋関数では項目比較、削除・移動・画像の依存関係、保留の保存・読み戻し、送信基準の更新を確認する。
画面では、本文と折りたたみの両方向、圏外の未送信記録、確認中と送信中の追加入力、
他の行の継続、保留中の再起動、通知の閉じ直し、サーバー側での解消、Undoを検証する。
既存の返事喪失・再送・1万行の未編集起動・端末保存・バックアップの試験も継続する。

コードhead `970f849` の[Linux CI run 40170054677](https://github.com/yohyng/taskapp/actions/runs/40170054677)で、
単体401件、Chromium/WebKit同期266件、既存アウトライン・Drive画面155件とビルドがすべて成功した。
Vercelプレビューも成功。WindowsのWebKitで時間切れになった既存の1万行保存試験も、Linuxでは成功した。
