# アウトライン同期の回帰テスト

`npm run test:sync` でChromiumとWebKitの両方を確認する。
初回は `npx playwright install chromium webkit` でブラウザを用意する。

通常のUI回帰テストとは別の4174番ポートでViteを動かす。
実際のOutlineProvider・Outliner・IndexedDBを使い、db.jsの通信境界だけを
Playwrightのrouteで差し替える。本番Supabaseの鍵は使わず、外部HTTPも遮断する。
このfixtureはテスト用HTMLで、本番の入口やビルド設定には追加しない。

全件削除、再起動、IndexedDBだけに残った空の木、未送信行の保護、
取得失敗、削除後の書き始めを確認する。
SupabaseのRLS・Realtime・実機の休止復帰まで確認するテストではない。

通常の `npm test` とは分けて、順番に実行する。
GitHub Actionsは単体テスト→同期テスト→既存アウトラインUIテストの順に動く。

送信の返事を止める試験では、待っている間の編集・削除が完了後に送られること、
送信を重ねないこと、失敗後に最新の内容で再試行することも確認する。

`localstore.spec.js` はアプリを起動しない専用HTMLから保存ヘルパーを読み、
実際のIndexedDBで保存・読み出し・削除の `complete`／`abort` を確認する。
要求の成功直後に取引を中断する試験と、要求エラー・複製エラーも含む。
中断した保存・削除が元の内容を壊さず、次の保存を続けられることを確かめる。
容量不足そのものやOSによる強制終了を再現する試験ではない。

端末保存の画面テストでは、localStorageの書き込みを容量不足にし、
保存ヘルパーの返事を制御して失敗や待機を再現する。成功時は実際のIndexedDBへ残す。
片方だけの失敗と両方の失敗を分け、手動／自動の再試行、書き出し、
起動時の失敗、古い返事が新しい編集へ影響しないこと、同期エラーとの併存を確認する。
ヘルパー自体の取引中断は `localstore.spec.js` で別に確認する。
起動時の読み出し失敗も区別し、書きかけの退避中は保存済みの本体を上書きしないことを確認する。

Realtimeの通知はfixtureから任意の時点で投入できる。移動前の古い行が届いても
親・並び順を戻さないことと、正しく新しい編集は受け取れることを確認する。
削除した直後、250msの受信待機中、送信中、失敗後の再試行待ちに届く行を遮断し、
取り消しで印を外すこと、やり直しで付け直すこと、再起動後も削除を送ることを確認する。
子孫を含む削除と、同期済みの覚えにまだ無い新規行も対象にする。
